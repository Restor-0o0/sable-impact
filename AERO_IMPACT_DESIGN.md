# Create Aeronautics Impact — дизайн-документ мода

**Название:** `Create Aeronautics Impact` (modid: `create_aeronautics_impact`)
Альтернативы: *Groundbreaker*, *Contraption Crash*, *Terrain Plow*, *Aeronautics: Debris*.

**Одной строкой:** аддон к **Create: Aeronautics**, при котором физические контрапшены («штуковины») при столкновении с блоками мира выбивают/раскидывают блоки, при этом расход кинетической энергии на разрушение и анти-бур буфер не дают штуковине зарыться до низа мира.

---

## 0. Статус реализуемости (честно)

| Часть | Реализуемо | Риск | Комментарий |
|---|---|---|---|
| Спавн разлетающихся блоков | ✅ да | низкий | ванильный `FallingBlockEntity` + `setDeltaMovement` (как TNT) |
| Прочность/«плотность» блока | ✅ да | низкий | `BlockState.getDestroySpeed` и/или `getExplosionResistance` |
| Энергетический бюджет (анти-бур) | ✅ да | низкий | чистая математика поверх скорости/массы |
| Доступ к массе/скорости/импульсу контрапшена | ✅ да | низкий | публичный API Sable: `PhysicsPipeline`, `MassData` |
| Хук «контрапшен коснулся блока» | ✅ да | низкий | публичный API Sable `BlockSubLevelCollisionCallback` — см. раздел 6 |
| Производительность | ✅ управляемо | средний | лимиты на тик, батчинг, режимы разрушения |

**Вывод:** мод реализуем, принципиальных «unknown» не осталось. Ключевое открытие:
физику даёт не CA, а библиотека **Sable**, и у неё есть публичный API коллизий блоков.
Ковырять внутренности CA не требуется — мод работает с любым сабуровнем Sable,
а CA просто самый популярный их поставщик.

**Проверено (август 2026):** NeoForge / MC 1.21.1; Sable 2.0.3, Create 6.0.10, CA 1.3.0.

## 1. Целевая механика (что видит игрок)

1. Штуковина летит/падает и врезается в поверхность.
2. Из зоны контакта **вылетают блоки** (как от взрыва TNT), разлёт по нормали столкновения + рандом.
3. Мягкие материалы (снег, лёд, земля, песок, листва) разлетаются/исчезают легко и глубоко.
4. Плотные материалы (камень, руда, обсидиан) сопротивляются: раскидывается мало, штуковина быстро тормозит.
5. **Штуковина не бурится бесконечно** — она встаёт, когда «энергия удара» израсходована на разрушение блоков и/или уперлась в слишком плотный слой.
6. Тяжёлая компактная штуковина продавливает глубже в плотные блоки, чем лёгкая крупная (эффект давления).
7. **Штуковина тоже разрушается.** Если она врезалась в материал прочнее собственного — крошится
   она, а не мир: земляная баржа об обсидиан теряет землю, обсидиан цел.

## 2. Физическая модель

### 2.1 Вход на каждый тик коллизии
Из физтела CA получить:
- `m` — масса контрапшена (или суммарная масса блоков контрапшена как прокси, если массы нет);
- `v` — вектор скорости в точке/зоне контакта;
- `n` — нормаль столкновения (направление «из поверхности»);
- набор блоков зоны контакта `contactBlocks` (воксели мира, пересечённые/касаемые коллайдером за этот тик).

### 2.2 Энергия удара
```
E_impact = 0.5 * m * v_n^2            // v_n = проекция скорости на нормаль n
```
`E_impact` — «бюджет разрушения» на этот тик контакта.

### 2.3 Давление (скейл по весу/компактности) — РЕАЛИЗОВАНО
```
A_contact  = max(1, число контактов этого сабуровня за тик)   // площадь контакта
pressure   = m / A_contact                                     // кг на блок контакта
massFactor = clamp((pressure / referencePressure)^massSensitivity, massFactorMin, massFactorMax)
breakSpeed_eff = breakSpeed / massFactor
```
Тяжёлая маленькая → высокий `pressure` → `massFactor > 1` → ломает то, что иначе устояло бы.
Лёгкая крупная → `massFactor < 1` → буксует даже на среднем грунте.

Множитель `|v_n|` из исходной формулы убран намеренно: скорость уже стоит по другую сторону
неравенства (`|v_n| >= breakSpeed_eff`), и учёт её дважды только искажал бы порог.
`massFactor` зажат в `[min, max]`, поэтому неизвестные единицы массы Sable не могут увести
поведение в абсурд — худший случай равен модели без массы, умноженной на константу.

Площадь контакта берётся из **предыдущего** тика (за текущий она ещё копится), ключ —
`ServerSubLevel.getRuntimeId()`.

### 2.4 Стоимость блока (материал = «плотность»)
```
cost(block) = k_material * f(resistance)
resistance  = max(getDestroySpeed, c * getExplosionResistance)   // подобрать
```
Табличные множители материалов (перекрываемы конфигом):

| Категория | Пример блоков | k_material (стоимость) | Поведение |
|---|---|---|---|
| очень мягкие | снег, листва, свежий снег | 0.1 | разлетается/исчезает всегда |
| мягкие | земля, песок, гравий, лёд, глина | 0.3 | легко раскидывается, глубоко |
| средние | дерево, шерсть, песчаник | 0.7 | умеренно |
| плотные | камень, булыжник, руды, кирпич | 1.5 | почти не летит, тормозит |
| очень плотные | обсидиан, незерит-блок, бедрок* | 5.0 / ∞ | не разрушается (бедрок = стена) |

\* бедрок и «неразрушаемые» (blast resistance ≥ порога) — только стена/отскок, никогда не ломаются.

### 2.5 Разрешение блока к разрушению
Блок из `contactBlocks` разрушается, если:
```
pressure >= threshold(block)     AND     E_remaining >= cost(block)
```
где `threshold(block)` растёт с плотностью материала. Каждое разрушение уменьшает бюджет:
```
E_remaining -= cost(block)
```
Когда `E_remaining` кончается — оставшиеся блоки НЕ ломаются (это и есть естественная остановка бурения).

### 2.5a Кто именно ломается — РЕАЛИЗОВАНО

Колбэк на блоке террейна получает **обе стороны контакта сразу** (`hitBlockPos` — мир,
`otherHitBlockPos` — блок штуковины), поэтому выбор жертвы делается в одном месте:

```
r_terrain = resistance(мир)
r_ship    = resistance(блок штуковины) * contraptionBlockToughness
жертва    = та сторона, у которой resistance МЕНЬШЕ
             (и только если её собственный breakSpeed пробит скоростью удара)
ничья     → ломается террейн
```

Оба порога делятся на общий `massFactor` из 2.3: больше давление — хуже обеим сторонам.

| Штуковина | Террейн | Итог |
|---|---|---|
| земля | обсидиан | крошится **штуковина** |
| камень | земля | ломается **террейн** |
| камень | камень | ломается **террейн** (ничья в пользу мира) |
| бедрок | земля | ломается **террейн** |
| обсидиан | обсидиан | не ломается никто, отскок |

Когда крошится штуковина, колбэк возвращает `CollisionResult.NONE`: террейн сохраняет коллизию
и штатно тормозит штуковину. То есть удар об обсидиан = и остановка, и потеря блоков.

Блок штуковины лежит в плотгриде (десятки тысяч блоков от игрока), поэтому обломок спавнится
там и переносится на `impactPosition` — в этой ветке она уже в **мировых** координатах
(javadoc Sable: глобальные, если блок не принадлежит сабуровню).

### 2.5b Штуковина о штуковину — РЕАЛИЗОВАНО

Та же функция `victim()`, поэтому жертва в `ImpactResolver` названа нейтрально по параметрам
самого Sable: `HIT` — блок, на котором висит колбэк, `OTHER` — блок встречного тела.
Обе стороны получают `contraptionBlockToughness`, так что сравнение чисто материал-против-материала.

Колбэк, судя по всему, срабатывает для блока на каждом теле, то есть контакт (A,B) даёт и вызов
`hit=A, other=B`, и зеркальный `hit=B, other=A`. Логика к этому устойчива:

- разные материалы → в обоих вызовах ломается **один и тот же** (мягкий) блок, второй вызов
  застаёт воздух и выходит;
- ничья → каждая сторона теряет свой блок, что для тарана равных кораблей и хочется.

**Масса — приведённая:** `m_eff = m1*m2/(m1+m2)`. При `m2 → ∞` она вырождается в `m1`, то есть
неподвижный террейн это частный случай той же формулы, а не отдельная ветка. Таран равного
корабля бьёт вдвое слабее, чем та же скорость об землю. Площадь контакта — максимум из
пер-сабуровневых счётчиков обеих сторон.

**Координаты обломков:** здесь `impactPosition` в координатах плота той штуковины, которой
принадлежит `hitBlockPos`, поэтому переводится в мировые через `logicalPose().transformPosition`
(проверено по байткоду: `world = orientation * ((src − rotationPoint) * scale) + position`).
Для этого понадобился артефакт `sable-companion` — `Pose3dc` живёт в нём.

### 2.6 Анти-бур буфер (демпфер вертикали)
Шелл толщиной 1 блок вокруг коллайдера. Считаем твёрдые блоки по горизонтали относительно движения:
```
lateral = число твёрдых блоков в боковом кольце
burrowDamp = clamp(1 - lateral / lateral_max, 0..1)
```
Чем сильнее штуковина «зажата» в грунте с боков — тем меньше разрешённое проникновение вниз за тик:
```
maxPenetrationThisTick = base_pen * burrowDamp * pressureFactor
```
Плюс жёсткий кап `PEN_CAP` (напр. ≤ 1 блок/тик).

### 2.7 Отдача в физтело (замыкание петли)
Энергия, ушедшая на разрушение, снимается со штуковины (импульс против движения):
```
E_spent = E_impact - E_remaining
apply impulse ≈ -n * g(E_spent)   // штуковина тормозит ровно на то, что разрушила
```
Если упёрлись в неразрушимый/слишком дорогой слой при израсходованном бюджете — полный резолв коллизии (стоп/отскок) штатными средствами CA.

**Итог анти-бура:** три независимых стопора — (а) энергия кончается, (б) давление ниже порога плотного блока, (в) буфер + PEN_CAP ограничивают вертикаль. Бесконечное бурение невозможно.

## 3. Разлёт блоков (визуал/выброс)

Режим на блок задаётся конфигом:

- **SCATTER** (по умолчанию): заменить блок на `air`, заспавнить `FallingBlockEntity` с
  `setDeltaMovement(n * base + random_scatter)`; TTL/кап на автоудаление, отключить дроп в предмет по желанию.
- **DESTROY**: снести блок (с дропом или без) без сущности — дёшево.
- **PARTICLE**: только партиклы + звук слома, блок в `air` — самое дешёвое.

Порог активации: если `|v_n| < MIN_IMPACT_SPEED` — ничего не делаем (штуковина просто лежит/едет медленно).

## 4. Производительность — РЕАЛИЗОВАНО

Главная стоимость нашлась не в самом коллбэке, а в том, что мод вешает коллбэк **на все блоки
подряд**. `VoxelNeighborhoodState.getState` (Sable) устроен так:

```java
if (isLiquid(state) || BlockWithSubLevelCollisionCallback.hasCallback(state))
    return CORNER;                 // ← собственный воксель, не сливается с соседями
...
if (allSolid) return INTERIOR;     // ← полностью замурован, сливается
```

То есть один наш миксин на `Block` отключал слияние вокселей для всего мира: каждый камень под
землёй становился отдельным коллайдером вместо того, чтобы уходить в общий блок. Отсюда и лаги.

Что сделано:

- **`VoxelNeighborhoodStateMixin`** (`@Redirect` на вызов `hasCallback` внутри `getState`, `require = 0`).
  Redirect дотягивается до аргументов `getState`, поэтому решение принимается **по позиции**, а не
  только по стейту: блок, замурованный со всех шести сторон, отдаётся Sable как обычный и снова
  сливается. Ударить его первым всё равно нельзя, а как только сломается сосед — Sable
  переклассифицирует его и воксель вернётся. Флаг `cullInteriorVoxels`, **по умолчанию выключен** —
  см. ниже.
- **Быстрый выход по скорости.** Подавляющая часть контактов, которые отдаёт пайплайн, — это
  лежачие и скользящие контакты с почти нулевой нормальной скоростью. Первое, что делает коллбэк —
  сравнивает `|impactVelocity|` с `minImpactSpeed` (точнее, с минимумом из него и порога хрупких
  блоков, 4.0 — иначе листва перестала бы ломаться); всё остальное (поиск sub-level,
  `getBlockState`, `getDestroySpeed`, чтение конфига) до этого сравнения не доходит.
- **`BlockProfile`** — кэш по `BlockState` того, что между ударами не меняется: прочность,
  неразрушимость, `sable:fragile`, отсутствие коллизии. Сбрасывается на перезагрузке конфига.
- **`ImpactConfig.Tuning`** — снапшот конфига одним объектом вместо ~15 `ConfigValue.get()` на контакт.

**Почему `cullInteriorVoxels` пришлось выключить по умолчанию.** `RapierPhysicsPipeline.handleBlockChange`
переклассифицирует только сам изменённый блок и его 6 соседей. Для ванильного Sable этого достаточно:
корпус физически не может оказаться внутри массива грунта. У нас может — мы сами прогрызаем туда путь.
Штуковина, пробившая поверхность, оказывается окружена блоками, рядом с которыми ничего не менялось,
все они `INTERIOR` (скрыты от генерации контактов) — и корпус проваливается сквозь землю как в воду,
сломав ровно один блок сверху. Именно это и наблюдалось. Флаг оставлен, но по умолчанию `false`.

Остаётся неустранимое: поверхностные блоки всё равно принудительно `CORNER`, иначе мод не получит
коллбэк. Если после этого останется дрожь на плоском грунте — причина здесь.

Прежние пункты плана, оставшиеся не сделанными: `MAX_FALLING_ENTITIES`, батчинг изменений блоков,
кулдаун на воксель.

## 4a. Блоки, сквозь которые штуковина пролетает — РЕАЛИЗОВАНО

Sable строит коллайдеры из ванильных `getCollisionShape`. У травы, цветов, лозы, паутины, факелов,
рельсов и тонкого снега форма пустая → воксель `EMPTY` → контакта нет вообще → коллбэк не
вызывается и сломать их нечем. Корпус их просто проглатывает.

Два независимых исправления:

1. **`HullSweeper`** (`LevelTickEvent.Post`) — раз в `softSweepInterval` тиков проходит по
   sub-level'ам, которые движутся быстрее `softSweepMinSpeed`. Чтобы не платить за объём корпуса,
   сканируются только **передние срезы** мировой AABB — по осям, где компонента скорости даёт хотя бы
   25% от модуля, толщиной по пройденному за интервал пути. Внутри среза: воздух — пропуск, не
   «мягкий» — пропуск, и только для найденного мягкого блока делается обратная трансформация
   (`Pose3dc.transformPositionInverse`) в координаты плота, чтобы проверить, что корпус реально
   занимает эту точку. Жидкости исключены явно — иначе штуковина осушала бы океан.
2. **Возврат `FragileBlockCallback`.** Наш миксин на `Block` перехватывал `sable$getCallback` раньше,
   чем Sable успевал проверить свойство `sable:fragile`, и тем самым ломал штатную обработку листвы,
   льда, кактусов, бамбука и кувшинок (тег `#sable:fragile`). Теперь `ImpactCallback` для таких
   блоков делегирует обратно в `FragileBlockCallback.INSTANCE`.

Чего это **не** чинит: почернение модели штуковины. Это освещение суб-уровня на стороне Sable/CA
(семпл света берётся по мировой позиции), а не наша механика разрушения. Косвенно должно стать реже
— корпус перестанет закапываться в грунт, когда пороги наконец работают.

## 4b. Пробитие насквозь vs. застревание — РЕАЛИЗОВАНО

Коллбэк возвращает `CollisionResult(tangentMotion, removeCollision)`. `removeCollision = true` выкидывает
контакт из шага — именно так Sable обходится с листвой, чтобы корабль не отскакивал от куста. Мы делали
так на **каждом** разрушении, и получалось, что грунт не забирает у тарана ни капли энергии: он
прогрызает блок за блоком с неизменной скоростью и вылетает с другой стороны.

Теперь контакт снимается только когда удар с запасом перекрывает порог блока
(`|v| >= breakSpeed * punchThroughRatio`, по умолчанию 2.5×). Ниже этого блок всё равно ломается, но
контакт остаётся и корпус получает от него импульс. Результат: таран роет, пока быстрый, тормозит по
мере углубления и в итоге **встаёт воткнутым** в грунт, а не пролетает насквозь.

## 4c. Штуковина внутри грунта — РЕАЛИЗОВАНО

Два твёрдых тела в одной точке — состояние, из которого солвер выйти не может. Штуковина, которую
дёрнули креативной палкой «текстурой в текстуру» или которая затормозила уже внутри стены, просто
залипает: контактов нет, значит и коллбэка нет, значит ломать нечего.

`HullSweeper` вторым проходом (`clearOverlaps`, раз в `overlapSweepInterval` тиков) идёт по всей мировой
AABB суб-уровня и сносит те блоки мира, **центр которых после обратной трансформации попадает внутрь
твёрдого блока корпуса**. Центр блока — это уже полблока проникновения, на порядок больше любого зазора
солвера, поэтому корпус, просто лежащий на земле, под это не попадает. Бедрок исключён.

Чтобы не сканировать объём каждого припаркованного корабля, проход работает только для суб-уровней,
которые двигались в последние `STUCK_GRACE_TICKS = 40` тиков **и уже остановились**. Залипший корпус
всегда встаёт резко, так что окна в две секунды хватает, чтобы он себя выкопал. Условие «уже
остановился» обязательно: без него проход выгребал грунт из-под ещё летящего корпуса, то есть не
высвобождал его, а копал за него.

## 4d. Разрушение вне шага солвера — РЕАЛИЗОВАНО

`sable$onCollision` вызывается **изнутри** `Rapier3D.step`. Любой `setBlock` оттуда уходит в
`SableCommonEvents.handleBlockChange` → `RapierPhysicsPipeline.handleBlockChange` →
`Rapier3D.newVoxelCollider`, то есть обратно в тот самый нативный физический мир, который сейчас
занят шагом. Серверный поток вставал в нативе намертво; watchdog печатал «a single server tick has
taken 283499 ms», а игрок видел вечное «Сохранение мира».

Поэтому коллбэк больше ничего не ломает сам: он кладёт запись в `PendingBreaks`, а разрушение
происходит в `LevelTickEvent.Post`, когда шаг уже вернулся.

Побочный эффект оказался важнее самого фикса. Раньше блок исчезал прямо в середине шага, и
`removeCollision = false` из раздела 4b ничего не значил — тормозить было уже не обо что. Теперь блок
стоит до конца шага, солвер честно отрабатывает о него контакт, и только потом блок пропадает.

## 4e. Почему штуковина проваливалась сквозь землю сама по себе — РЕАЛИЗОВАНО

Симптом: собрать столб из камня над однoблочным зазором — и он бесконечно уходит вниз, съедая всё
под собой. Складывалось из трёх вещей, каждая из которых сама по себе достаточна:

1. **Порог был ниже осадки.** Гравитация Sable — `DimensionPhysics.DEFAULT_GRAVITY = -11 м/с²`, то есть
   падение на один блок даёт 4.7 м/с. Порог камня выходил ≈4.4 м/с. Штуковина ломала блок под собой
   просто фактом сборки, падала на блок ниже, снова набирала 4.7 — и так до бедрока.
   Лечится тем, что `minImpactSpeed` стал **абсолютным полом**: масса облегчает только слагаемое
   прочности, но не пол (`effectiveBreakSpeed = minImpactSpeed + hardnessScale·resistance / massFactor`),
   а сам пол поднят до 6.0 — выше осадки на один блок.
2. **Разрушение ничего не стоило.** Убрать блок — не значит отнять импульс. Корпус, пробивший блок
   «бесплатно» (раздел 4b), продолжал разгоняться гравитацией, поэтому следующий слой давался легче
   предыдущего: разгон без обратной связи. Теперь на каждый пробитый насквозь блок в `PendingBreaks`
   копится импульс `breakDragMass · |v|` против движения (порядок «сколько массы корпус тащит за собой
   на своей скорости»), и в конце тика он одним `RigidBodyHandle.applyLinearImpulse` снимается с тела,
   с потолком в `m·v` — больше, чем остановить, нельзя.
3. **Подметатель копал.** См. 4c.

### Калибровка по реальной шкале Sable

Первые значения `referencePressure` и порогов прочности были угаданы и оказались мимо на порядок.

**Масса.** `PhysicsBlockPropertyTypes.MASS` по умолчанию **1.0 кг на блок**; датапак Sable даёт
`#sable:heavy` (камень, обсидиан, базальт) **2.0**, `super_heavy` 4.0, `light` 0.5. То есть вся
штуковина весит сотни килограмм, а не десятки тысяч. Обсидиановый стержень 4×4×16 = 256 блоков =
512 кг; при контакте торцом в 16 блоков это 32 кг на блок контакта. Со старым
`referencePressure = 400` `massFactor` упирался в нижний клэмп 0.5, то есть таран **поднимал**
себе порог вдвое вместо того, чтобы его опускать. `12.0` ставит шестиблоковый каменный таран в
нейтраль, а обсидиановый стержень — в множитель ~2.7.

**Прочность.** Ванильный разброс — три порядка: земля 0.5, камень 1.5, обсидиан
`max(50, 1200 × 0.25) = 300`. Линейно это давало обсидиану порог **451 м/с** — недостижимо, отсюда
«отскакивает как шарик, немного разрушая». `resistanceExponent = 0.5` сжимает шкалу, сохраняя
порядок:

| блок | R | порог, м/с | он же с тараном (massFactor 2.7) |
|---|---|---|---|
| земля | 0.71 | 2.8 | 1.0 |
| камень | 1.22 | 3.2 | 1.2 |
| глубокосланец | 1.73 | 4.1 | 1.5 |
| железный блок | 2.24 | 5.0 | 1.9 |
| обсидиан | 17.3 | 32.7 | 12.1 |

Таблица `materialCosts` из первоначального плана не понадобилась: прочность выводится из
ванильных `getDestroySpeed`/`getExplosionResistance` (раздел 2.4), что автоматически покрывает
и модовые блоки.

## 6. Точки интеграции — РЕШЕНО (Sable, не CA)

Главный «unknown» раздела 0 закрыт. Цепляться за CA не нужно вообще: физика живёт
в библиотеке **Sable** (`dev.ryanhcode.sable`, Rapier через JNI), у которой есть
публичный API коллизий блоков. CA — лишь один из потребителей Sable.

**Целевая платформа:** NeoForge, MC 1.21.1. Sable `2.0.3`, Create `6.0.10`, CA `1.3.0` (modid `aeronautics`).
Maven Sable: `https://maven.ryanhcode.dev/releases`, артефакт `dev.ryanhcode.sable:sable-common-1.21.1`.

**Хук столкновения** (заменяет пункты 1–3 старого плана):

```java
// dev.ryanhcode.sable.api.block.BlockWithSubLevelCollisionCallback
BlockSubLevelCollisionCallback sable$getCallback();          // реализуем миксином на Block

// dev.ryanhcode.sable.api.physics.callback.BlockSubLevelCollisionCallback
CollisionResult sable$onCollision(BlockPos hitBlockPos,
                                  @Nullable BlockPos otherHitBlockPos,
                                  Vector3d impactPosition,
                                  double impactVelocity);     // уже спроецирована на нормаль
record CollisionResult(Vector3dc tangentMotion, boolean removeCollision);
```

Sable сам применяет этот паттерн (`TntBlockMixin`, `FragileBlockCallback`) — мы вешаем миксин
на `net.minecraft.world.level.block.Block`, чтобы колбэк получили все блоки.

**Что это меняет в модели:**

- `v_n` (раздел 2.2) приходит готовым в `impactVelocity` — считать не нужно.
- `otherHitBlockPos != null` ⇔ второе тело это сабуровень. Это и есть дискриминатор
  «террейн, в который врезался контрапшен» против «блок контрапшена, ударивший мир».
- **Анти-бур получается бесплатно** через `removeCollision`: `false` — контакт резолвится
  штатно и физически тормозит/останавливает штуковину; `true` — блок исчез, штуковина проходит.
  Отдельный энергобюджет с ручным `applyImpulse` (раздел 2.7) для v1 не нужен.
- `SubLevelPhysicsSystem.getCurrentlySteppingSystem().getLevel()` даёт `ServerLevel` внутри колбэка.

**Масса ударившего сабуровня (раздел 2.3) — РЕШЕНО.** Колбэк не сообщает, *какой* сабуровень
ударил, но `otherHitBlockPos` лежит в координатах плотгрида, так что сабуровень доискивается
напрямую, без `queryIntersecting`:

```java
ServerSubLevelContainer c = SubLevelContainer.getContainer(serverLevel);   // api.sublevel
LevelPlot plot = c.getPlot(new ChunkPos(otherHitBlockPos));                // sublevel.plot
ServerSubLevel sub = (ServerSubLevel) plot.getSubLevel();                  // sublevel
double kg = sub.getMassTracker().getMass();                                // api.physics.mass.MassData
```

Бонусом `c.inBounds(hitBlockPos)` — авторитетная проверка «этот блок настоящий террейн, а не
внутренность плотгрида», строже прежней эвристики по `otherHitBlockPos != null`.

`MassData` также даёт `isInvalid()` (масса ≤ 0 — сабуровень ещё не собран), `getCenterOfMass()`,
`getInertiaTensor()`, `getInverseNormalMass()`. `ServerSubLevel.getRuntimeId()` — стабильный
ключ для пер-сабуровневой бухгалтерии за тик.

**Ещё не задействовано:** `PhysicsPipeline.applyImpulse` (раздел 2.7 — ручная отдача; для v1
не нужна, `removeCollision=false` тормозит штуковину штатной физикой).

## 7. План разработки (для модели)

1. Каркас мода: modid `create_aeronautics_impact`, зависимости Create + Create: Aeronautics, целевой loader/версия.
2. Config (раздел 5) + таблица материалов.
3. `ImpactResolver` — чистая функция: (m, v, n, contactBlocks, world) → список действий (какие блоки в какой режим, какой обратный импульс). Покрыть юнит-тестами БЕЗ движка.
4. Разлёт: `BlockScatter` (SCATTER/DESTROY/PARTICLE) + лимиты/капы.
5. Интеграция с CA через mixin (раздел 6); если хук не найден — fallback-свип (7.3).
6. Тюнинг чисел в игре: снег/земля разлетаются глубоко, камень тормозит, бедрок = стена, бурения до дна нет.
7. Оптимизация под лаги (раздел 4).
